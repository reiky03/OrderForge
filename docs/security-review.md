# Security review for the local demo

The API uses Sanctum bearer tokens for customers and admins. Policies scope customer order reads, cancellations, payments, and private `orders.{id}` WebSocket subscriptions to the owner; admin endpoints check the admin role. Login and webhook routes have rate limits. Mock payment simulation is available only in local/testing, while the raw webhook verifies an HMAC-SHA256 signature, timestamp tolerance, and unique provider event ID. Error responses carry a request ID without exposing exception traces; stderr logs are JSON with the same ID. Inventory changes require authorization and are committed with ledger and audit rows.

The local Compose file deliberately uses documented demo credentials and exposes its ports for review. Replace database, RabbitMQ, Reverb, webhook, and app secrets before using a shared environment; terminate TLS at a proxy and restrict management/metrics access. This repository is a portfolio demonstration and does not include a real payment gateway, secret vault, or production deployment manifest. The Management API consumer acknowledges a message before its database receipt; outbox reconciliation republishes unreceipted events, so integration consumers must remain idempotent. AMQP manual acknowledgements are a sensible production upgrade.

Checks performed: backend authorization/webhook/flow tests, PHP static analysis and formatting, frontend lint/build, real PostgreSQL checkout race, signed webhook duplicate smoke check, and readiness checks. The local production dependency audit returned zero high-severity frontend production vulnerabilities at the time of this run; development tooling still reports transitive advisories separately.
